0.4.0
Oct 6–7, 2026
GitHub Release

Making its own media

Until 0.4.0 Local Transcriber only worked with media that already existed. This version lets it make that media itself, and stops there.

Why record at all

Sometimes the thing to transcribe isn't a file yet: something said into the microphone, or audio playing in another app. Getting it in meant opening a different recorder, saving a file, finding it and dropping it onto the window. That is the same kind of repeated step 0.2 took out.

The obvious next step looks like a meeting assistant: listen all the time, transcribe live, separate the speakers, write a summary. I didn't want that. A recording had to become the same kind of media the app already handled, and nothing more.

One more way in

Record sits next to Add Files. It opens a small panel with two choices: the microphone, or one running app with the microphone as an option. Nothing is captured until you press Start Recording, and while it runs the window shows what is being recorded and for how long.

Stop saves one M4A file to your output folder, named after the time and the source, and adds it to the queue as if you had dropped it there. It is transcribed on the Mac like any other job, and the timestamped Markdown lands next to the recording, which stays as the source and is never deleted automatically.

One app, not the whole Mac

For app audio you choose one running app, and Local Transcriber asks macOS to capture that app only. Recording the whole system is not offered. A recording should stay tied to what you chose to record.

That choice decided how it was built. My first attempt used Core Audio process taps, but an app's sound often comes from a helper process: Safari, for example, plays through a WebKit helper. Recording "Safari" would have meant finding and following those helpers myself. ScreenCaptureKit already counts a helper's audio as part of its app, so it replaced the taps.

App audio uses the macOS Screen & System Audio Recording permission, and the microphone uses its own. Each is requested the first time you use that kind of recording, not at launch. Local Transcriber does not save or retain video or screen recordings.

Most of the work doesn't show

Recording starts only once there is an output folder to save into. While it runs, nothing is written there: the audio stays in the app's own storage and moves to the folder only when it is complete and checked. If the folder disappears in the meantime, the app holds on to the recording and asks where to save it. If no sound arrives for ten seconds, the window says so, without guessing that a permission is missing; a denied permission is reported only when macOS reports it.

0.4.0 shipped signed and notarized, and the app from the final DMG transcribed a recording, a local file and a YouTube link.
