0.7.0
Oct 15–17, 2026
GitHub Release

Where transcripts live

0.6.0 let me read a transcript while I listened to it. 0.7.0 is about everything around that: every transcript now gets its own folder in a library I can organize, and a transcription starts the moment I hand the app something. The speech recognition and the Markdown are the same as in 0.6.

A library that could only look

0.6.0 could already open a transcript, show its timestamps and play the recording from any line. What it couldn't do was keep transcripts in order. The sidebar was a view of the output folder, and every transcript in it was a loose Markdown file with its timing file beside it. A recording was an M4A with a date in its name, sitting next to them. Only a YouTube source package got a folder of its own.

The list showed the Markdown's modification date as the day it was saved, so a file I had touched looked newer than it was. And the app couldn't do anything with a transcript except open it. Renaming one, sorting them or clearing out old ones meant going to Finder. There, renaming the Markdown on its own meant it opened without its timestamps, because the app finds the timing file by the Markdown's name.

One folder per transcript

Now every new transcription gets its own folder, named after the media. It holds the Markdown and its timing file, and for a recording the audio too. Next to them sits a small entry.json: when the transcript was created, and whether it is pinned, archived or not opened yet. It's a few hundred bytes and it lives inside the folder, so a rename or a move in Finder takes it along. The title is simply the folder's name.

With that in place, the rest was straightforward. Rename changes the folder, the Markdown file and the timing file to the same new name, never the text, and the creation date stays. Pin keeps a transcript at the top. Archive tucks it away and changes nothing on disk except entry.json. Move to Trash asks first and never deletes anything permanently. Folders I create in the app are ordinary folders in the output folder, so Finder shows them too; in this version I move a transcript into one from its context menu.

There is still no database. The app scans the output folder and the folders directly inside it, nothing deeper, and a change made in Finder shows up after a refresh. Transcripts from 0.6 and earlier are listed and open as they are. Nothing is migrated.

Hand it something and it starts

The queue dates from 0.2, when one file at a time wasn't enough. It had its own page and its own steps: add items, give each one a language, press Start, apply one language to everything waiting, clear what had finished. For 0.7.0 I decided that Local Transcriber is not a batch queue manager. The queue page is gone, and so are Start, Apply Language to All Waiting, Clear Queue and the per-item language.

Instead, one transcription runs at a time for the whole app. It starts as soon as a file, a YouTube link or a finished recording is accepted, using the language chosen at the bottom of the window at that moment. While it runs, or while a failed or unsaved job is still waiting, any other input is refused with an explanation. It is never queued or dropped without saying so, and Record isn't offered. That way, a finished recording goes straight into transcription without another step.

The running job sits in a Processing section above the library, so the library stays usable while it works. It shows the stage, and how far the recognizer has got through the audio against the total length. That number never goes backwards, and there is no guess at when it will finish. English moves every few seconds. Dutch comes in steps of about a minute of audio, because that is how often the recognizer reports back. When it's done, the transcript appears in the library with a New badge until I open it. The app doesn't jump to it, so I can keep reading something else.

This has a cost. I can't line up a stack of files and walk away anymore: dropping several at once is refused as a whole. Quitting the app while a transcription runs ends it without asking, and the job isn't picked up again at the next launch. What goes is the transcription in progress, not anything already on disk. The original local media file is untouched. A recording's audio is already saved in its own folder, while a temporary YouTube download is cleaned up at the next launch. Adding the same input again starts over.

The window got calmer in the same release, with one New control and a title bar that says where I am. And Dutch transcripts can still come back thin. The problem 0.6.0 started with is still there.
