0.1.0
Sep 27–28, 2026
Development build

It started with one file

The first version did one job: take a recording, run Apple's speech recognition on the Mac, and hand back a timestamped Markdown file.

The whole loop

I built it over two days, September 27 and 28. It was a native macOS app with a drop target. You dropped in an MP4, MOV, M4A, MP3 or WAV file, picked one of ten languages and pressed Transcribe. For video, AVFoundation first copied the audio into a temporary M4A. Apple's on-device speech stack then did the recognition and returned the text in timed segments.

Save Transcript… wrote the result to a Markdown file. The title came from the filename, a few lines of metadata followed, and the text was grouped by minute under a timestamp heading. The tagline was there from the start: media in, Markdown out.

Why it stays on the Mac

The media was already on my Mac, and I didn't want to send it somewhere else to get text back. So there was no account, no cloud transcription service and no model picker. Apple's speech stack is part of macOS, which meant the app didn't have to ship a model of its own. The only network traffic was macOS fetching Apple's language assets the first time a language was used.

Every run also showed the media duration, how long processing took and the speed relative to realtime.

Where it stopped

0.1.0 was a version number in the Xcode project. By the end of the second day the code had an MIT license and a README, but there was no GitHub Release, no signed build and no installer.

It also handled exactly one file at a time. Each transcript went through its own Save dialog, and the next file meant starting again from the empty window. With one recording you barely notice that. With five you notice it a lot, and that is where 0.2 begins.
