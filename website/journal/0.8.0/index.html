0.8.0
Oct 17–25, 2026
GitHub Release

Nothing lost on the way out

0.7.0 gave every transcript a place to live. 0.8.0 is a set of smaller changes that came from using it: a recording survives closing the window, transcripts move by dragging them onto a folder, the output folder sits where it is used, and a transcript can start with a YAML header for Obsidian. The speech recognition is the same as in 0.7, and so is the Markdown unless I turn that header on.

A recording could disappear

Until now, closing the window while it was recording ended the recording without asking, and so did quitting the app. What had been captured never reached the output folder. For a tool whose whole job is to keep what was said, that was the worst kind of failure: silent.

Now both ask first. Keep Recording is the default, and Escape picks it too. Stop and Save stops, saves the audio and waits until the file is really in the output folder before it lets go. Closing the window then transcribes the recording in the background, as if I had pressed Stop. Quitting saves only the audio and says so: the app is about to go away, so it doesn't start a transcription it can't finish, and I can add the audio again later like any other file. If the save fails, for example because the output folder is gone, the window stays open until I choose another folder.

A crash or a force quit still loses a recording. That is a different problem, and this version doesn't solve it.

Things where they are used

The output folder used to be a row in Settings, far from where it matters. It now sits in the footer of the window as "Saves to" and the folder's name, next to the language menu that decides how the next transcript is made. A click chooses another folder, a right-click shows it in Finder, and while something is transcribing or recording it can't change.

Folders in the library came with 0.7.0, but moving a transcript into one meant a context menu. Now I drag it onto the folder, from Recent, from Pinned or from another folder. The files and their metadata go along unchanged, a name that already exists in the folder is refused with a message, and a transcript that is open stays open. If it is playing, it keeps playing from the same point.

Settings also got an Appearance choice. System follows macOS; Light and Dark stay put whatever macOS does.

A header for Obsidian

Obsidian reads a YAML block at the top of a note as its properties, so in Settings there is now Add YAML Frontmatter to New Transcripts. It is off by default. When it's on, a new transcript starts with the source, the language, the transcriber, the duration in seconds and, when the app knows it, when a recording was made or when a YouTube video was published. There is no title, because the folder's name already is one, and a value the app doesn't know is left out rather than guessed.

Below the block is exactly the Markdown the app would have written without it. Turning the setting on or off never touches transcripts that already exist. Copy leaves the block out, so pasting a transcript somewhere else gives the text and not the metadata.

A window that was busy doing nothing

While working on this release I saw the app use close to a full CPU core whenever its window was in front, even with nothing happening. The menu commands were being rebuilt on every pass of SwiftUI, and each rebuild caused another pass. With that fixed, the idle window uses practically nothing. The fix briefly broke something else, ⌘V right after a language change used the old language, and that is fixed too. Neither problem reached a public version before this one.

Dutch transcripts can still come back thin.
